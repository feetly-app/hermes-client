# CLAUDE.md

Instructions for Claude Code in this repository.

## Project

Native SwiftUI client (iPhone, iPad and Mac; iOS 27 / macOS 27) for a self-hosted Hermes Agent instance (OpenAI-compatible API). Personal use only. The work plan lives in the GitHub milestones and issues (M0 to M6).

## Language

Everything in the repository is written in English: code, comments, tests, docs, commit messages, PRs and issues.

## Architecture

- `HermesKit/`: local SPM package holding all the business logic, testable without UI.
  - `HermesAPI`: HTTP client (`URLSession`), SSE parsing (`URLSession.bytes`), Codable models, typed errors. Every path lives in `HermesAPIPaths`:
    - sessions: list, get, rename (`PATCH`), delete, messages, fork and chat stream under `/api/sessions`;
    - `/health` (unauthenticated, no longer used by "Test connection");
    - `/v1/models` and `/api/model/options` (provider model catalog) for the model settings, with a manual fallback.
  - `HermesChat`: conversation logic. Every conversation is a session stored on the Hermes instance (created, listed, renamed, deleted and continued through `/api/sessions`); the app keeps no copy of the messages.
    - `ConversationBrowser`, `RemoteSessionList`, `RemoteTranscript`: session list, open transcript, sending and live replies. A session created elsewhere (web dashboard, TUI) is forked into an API session on the first message.
    - Transcript activity (`ActivityStep`): tool calls, reasoning and background agents shown in the transcript.
    - `MarkdownParser` (`MarkdownBlocks.swift`): markdown parsing (headings, lists, quotes, rules, tables, code). `LongText`: truncation of very long messages.
    - Search by title (`SessionSearch.swift`), `SessionKind` (icon per session kind), `ModelChoice`.
    - Images: `PendingAttachments` for the composer. Hermes does not return the images of stored messages, only `[Image attached at: …/<sha256>/<name>]` markers (`StoredImageMarkers`); `StoredImageLoader` gets them back from the sidecar (`GET {sidecar}/media/{sha256}`) and keeps them in `Caches/Message Images`. Without a sidecar they show as not available.
    - `ConnectionSettings` (URL, model, provider, optional sidecar location, stored in `UserDefaults`, never secrets) and `ConnectionTester` ("Test connection": an authenticated `GET /api/sessions?limit=1` on Hermes, since `/health` ignores the key, and `GET {sidecar}/status` through `SidecarClient` when a sidecar is set). The sidecar (hermes-sidecar, same API key) is a path on the instance URL or a full URL; the app works without one.
  - `HermesSecurity`: `SecretStore` protocol and `KeychainSecretStore`, used by the app for the API key. Supports iCloud Keychain sync (`synchronizable`), off by default and not exposed in the UI.
- The app (`App/`: views, navigation, dependency injection in `AppState`) contains UI only: conversation sidebar and chat view, floating composer (send on Return, add-to-message sheet with recent photos and camera), markdown rendering, activity view, scroll-to-bottom button, settings sheet, Mac keyboard shortcuts (Command-N for a new conversation). The Xcode project is generated by Tuist from `Project.swift`: never commit or edit the `.xcodeproj` / `.xcworkspace`, change the manifest and regenerate instead.
- The API client is built from an explicit configuration (URL + key). No global singleton.

## Conventions

- Swift 6, strict concurrency. `swiftLanguageModes: [.v6]`.
- Concurrency: `async/await`, `AsyncThrowingStream` for streaming, `Sendable` wherever a value crosses an actor boundary.
- Observation: `@Observable`, not `ObservableObject`.
- Tests: Swift Testing (`import Testing`, `@Test`, `#expect`). Network mocked through a custom `URLProtocol`. SSE fixtures stored in files.
- No third-party dependencies. Apple frameworks only.
- No secrets, real URLs or keys in code, tests or fixtures. Use `https://hermes.example.test` in tests.
- POST requests are never retried automatically. Generous timeouts (an agent request can take ~30 min).

## Commands

```sh
# Tooling (Tuist, version pinned in mise.toml)
mise install

# HermesKit package tests (swift test --package-path HermesKit)
mise run test

# Generate the Xcode project, then build the iOS or macOS app
mise run generate
mise run build
mise run build-mac

# App tests on an iOS 27 simulator (set IOS_DESTINATION to pick another simulator)
mise run test-app
```

CI: `.github/workflows/ci.yml` runs the HermesKit tests and builds the app for iOS and macOS on every PR and on `main`, on the `xcode-27` runner (macOS 27 + Xcode 27 preview image). App tests are slow and add little since the business logic lives in HermesKit, so they only run locally via `mise run test-app`.

Previews: adding the `preview-ios` or `preview-macos` label to an open PR runs `.github/workflows/preview-ios.yml` (ad hoc signed IPA + iOS Simulator build) or `preview-macos.yml` (ad hoc signed Mac app) and shares the builds as Tuist Previews. The label is removed when the run starts: add it again to rebuild.

## Git

- One issue = one branch = one PR. Branch `feat/<m>-<slug>` or `fix/<slug>`.
- Conventional Commits, small and clear.
- Never mark an issue Done unless its acceptance criteria are met and tests are green.

## Open questions

Items tagged `needs-verification` in the issues are assumptions about the Hermes API (health check path, `GET /v1/models`, `GET /api/model/options`, iOS background behavior; see the comments in `HermesAPIPaths`). Do not hard-code these assumptions without verifying them, and keep an abstraction that is easy to adjust.
